JuanAI Developer API

FootballCasinoServer-to-server

1. Create credentials

In JuanAi Admin → Developer API, select Football API, Casino API, or both. If both are selected, JuanAi creates two independent credentials. A Football credential cannot access Casino endpoints and vice versa.

The secret is displayed only when the credential is created or rotated. Store it securely on your backend.

2. Authentication

X-JuanAI-Key: jsk_football_...
X-JuanAI-Secret: jss_football_...

Credentials must stay server-side. Do not put them in browser JavaScript, localStorage, mobile-app public bundles, logs or Git.

3. Product isolation

Football key → /api/developer/football/*  ✓
Football key → /api/developer/casino/*    ✗ 403
Casino key   → /api/developer/casino/*    ✓
Casino key   → /api/developer/football/*  ✗ 403

4. Errors

{
  "success": false,
  "error": {
    "code": "INVALID_API_CREDENTIALS",
    "message": "The API credentials are invalid."
  }
}

Common codes: INVALID_API_CREDENTIALS, API_KEY_REVOKED, INSUFFICIENT_SCOPE, INVALID_REQUEST, MISSING_PARAMETER, RESOURCE_NOT_FOUND, UPSTREAM_ERROR, RATE_LIMITED, INTERNAL_ERROR.

5. Rate limiting

The Developer API is rate limited per credential. The default implementation allows 120 requests per 60-second window. Configure DEVELOPER_API_RATE_LIMIT and DEVELOPER_API_RATE_WINDOW_MS on the server if different limits are required.

6. cURL

curl "https://YOUR-JUANAI-DOMAIN/api/developer/football/fixtures?days=0" \
  -H "X-JuanAI-Key: YOUR_FOOTBALL_KEY" \
  -H "X-JuanAI-Secret: YOUR_FOOTBALL_SECRET"

7. Node.js

const response = await fetch(
  'https://YOUR-JUANAI-DOMAIN/api/developer/football/fixtures?days=0',
  {
    headers: {
      'X-JuanAI-Key': process.env.JUANAI_FOOTBALL_KEY,
      'X-JuanAI-Secret': process.env.JUANAI_FOOTBALL_SECRET
    }
  }
);
const data = await response.json();

8. Real-money wallet status

The existing JuanAi wallet bridge remains the source of truth for current integrations. The new Developer API does not create fake balance/bet/win endpoints. Production wallet operations are explicitly marked pending until a real provider callback/transaction implementation is present and tested.
