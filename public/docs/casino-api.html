JuanAI Casino API

For betting sites integrating JuanAI casino games. Each betting site receives a dedicated jcas_... API key and secret.

Wallet model

JuanAI does not hold the player's authoritative balance. The betting site's wallet remains the source of truth. JuanAI calls the operator wallet for balance, debit, credit and refund/rollback.

Authentication

Send these headers on every request:

X-JuanAI-Casino-Key: jcas_...
X-JuanAI-Timestamp: 1760000000
X-JuanAI-Signature: HMAC_SHA256(secret, timestamp + "." + rawBody)

For GET requests the raw body is empty. Reject timestamps older than 5 minutes.

Endpoints

GET  /api/v1/casino/games
GET  /api/v1/casino/balance?playerId=PLAYER_ID
POST /api/v1/casino/session
POST /api/v1/casino/bet
GET  /api/v1/casino/bet/:betId
POST /api/v1/casino/bet/:betId/cashout
GET  /api/v1/casino/history?playerId=PLAYER_ID&limit=50

Create session

POST /api/v1/casino/session
{"playerId":"player-123","username":"demo"}

The response includes a signed JuanAI user token and the current balance read from the betting site's wallet.

Place bet

POST /api/v1/casino/bet
{"gameId":"aviator","playerId":"player-123","slot":1,"stake":100}

JuanAI first requests a real debit from the betting site's wallet. A game bet is not accepted when that debit is rejected.

Win and cashout

When a bet wins, JuanAI requests a credit from the same betting-site wallet. If the bet cannot be placed after a successful debit, JuanAI requests a refund. Transaction references are used for idempotency by the wallet integration.

Credential separation

jcas_... credentials work only with Casino API routes. They cannot authenticate Game API routes or the legacy jsk_... API.
